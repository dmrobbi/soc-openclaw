soc-openclaw

A step-by-step guide to a home SOC where OpenClaw is the always-on AI analyst: it watches your host's logs and security tooling in real time, runs scheduled sweeps, triages what it finds, and pages you on your chat channel.

What it does

  • Real-time stream triage: a supervised tail -F automation with a match pattern pages you after thinking — "12 attempts from 203.x, fail2ban banned them" — not with a raw log dump. batchMs folds a burst of matches into one alert.
  • Scheduled sweeps: a written skill (the agent's playbook) runs a morning and end-of-day check across failed units, journals, fail2ban state, logins, sockets, disk and pending updates — and reports one line per finding, or a single clean line.
  • Optional Wazuh SIEM tier with a pull pattern: a 5-minute job that reads the newest alerts within its own computed window — stateless, so it survives restarts without losing or double-sending anything.
  • Hardening-first setup: the guide hardens the host (firewall, keys-only SSH, unattended security updates) before anything connects agents, and keeps the Control UI behind SSH tunnel or Tailscale.
  • Built from maintained tools: fail2ban, auditd, Wazuh, OpenClaw — glue, not a custom SIEM. The docs carry the architecture, the deploy guide, fleet onboarding, and a simple-install path.

What it does NOT do

Not an enterprise stack. This is a home-lab SOC for one operator. No multi-tenant anything, no compliance regimes bundled in, no SLAs. (The compliance/commercial layer is Bedim Security's separate work.)

It does not nuke. The agent triages and recommends; it never auto-runs destructive remediation — no bans, deletes, or service restarts without a human confirming.

It does not cry wolf. Quiet hours are an explicit rule; "none = quiet, do not page me" is part of the job text; alerts batch and dedupe aggressively, because a SOC that pages every five minutes gets muted on day two.

No custom detection code: the project deliberately composes existing, maintained tooling; the interesting part is the supervision, the triage prompts, and the evidence trail — not reimplementing a SIEM.

Quickstart

git clone https://github.com/dmrobbi/soc-openclaw.git && cd soc-openclaw
# guides: quickstart.md, docs/SIMPLE-INSTALL.md, docs/deploy-guide.md

# Step 0: a Linux server with sudo, Node.js 20+, a chat bot (Discord/Telegram token)
npm install -g openclaw      # Step 1: install + onboard the gateway
openclaw                     # first run walks through onboarding
openclaw status              # verify health + channels

Then Steps 2–9 take you through: connecting the chat channel, hardening the host, baseline tooling (fail2ban/auditd), the SSH stream job, the sweep skill + its cron, the optional Wazuh tier, an end-to-end pipeline test, and operating rules. Each step carries copy-paste automation JSON.

Methodology (dated)

  • Release: v0.1.0, tagged 2026-10-19, with a dated CHANGELOG; the guide reflects a deployed, production-proven instance (hardened host, stream + sweep + SIEM tiers all live).
  • Method: compose existing tools; supervised stream automations for line events; stateless pull windows for SIEM alerts (restart-safe by construction); skills as the agent's written playbooks; report-only remediation posture with human confirmation gates.
  • Docs: docs/architecture.md, docs/deploy-guide.md, docs/fleet-onboarding.md, docs/SIMPLE-INSTALL.md, docs/security-notes.md carry the deeper layers.
